# shinhan-uw 데이터 정제 — 무엇을 왜 했는가

대상: 신한라이프 언더라이팅 실무문서 7건의 파싱본
(`0730 임시 검증/parse_results_json/*.json`, pdf 3 / xlsx 3 / pptx 1)
목적: dr-dci Part 1(증강 적층) · Part 3(태그 스킴) · Part 4(DR-DCI vs Hybrid)로
**시멘틱 태그와 메타데이터가 검색을 개선하는지** 측정할 수 있는 코퍼스로 만든다.

빌더: `scripts/build_shinhan_uw_corpus.py` (LLM·임베딩 호출 없음, 결정론적)

---

## 0. 입력 실측 — 정제가 필요한 이유

| 항목 | 실측값 |
|---|---|
| 문서 | 7건 (pdf 3 / xlsx 3 / pptx 1) |
| 파서 블록 | 441개 |
| 블록 라벨 분포 | `table` 367 · `text` 48 · `paragraph` 19 · `header` 3 · `paragraph_title` 2 · `infographic` 1 · `vision_footnote` 1 |
| `blocks[].text` 총량 | **608,401자** |
| `markdown` 총량 | **38,756,263자 (63배)** |
| 최대 단일 블록 | `간편예외질환 Board` — text 116,155자 / markdown **18,370,854자** |
| 문서 내 완전중복 블록 | **156/441 (35%)** — `건강 전상품` 111, `메디컬UW` 31, `기계약` 12 |
| 계층 정보 | **없음** (parent/section 포인터 부재, 배열 순서만 존재) |
| `bbox`/`score` | PDF에만 존재. xlsx는 키 자체가 없고 pptx는 null |

파싱본은 **블록 라벨을 실제로 준다**. 기존 `build_shinhan_corpus.py`는 md에서
정규식으로 element_type을 추측하고 `build_tags.py`는 LLM으로 다시 추측하는데,
여기서는 파서 라벨이 있으므로 "LLM 증강" vs "파서가 공짜로 주는 사실"을
같은 실험 안에서 비교할 수 있다 → Part 1 `parser_meta_only` arm.

## C1. `blocks[].text`만 쓰고 `markdown`은 버린다

**왜.** markdown이 63배 큰데 의미 정보는 0이다. 파이프 표를 공백으로 열 정렬하고
병합 셀 값을 모든 열에 복제한 결과다. 단일 블록 하나가 18.3M자로,
어떤 청커·임베더에도 넣을 수 없다.

## C2. 거대 표 블록을 행 그룹으로 쪼개고 헤더행을 매 그룹에 반복 삽입

**왜.** `retriever.py:96-98`이 임베딩 입력(`title + text`)을 4,096자에서 자른다.
`간편예외질환 Board`는 232K자가 블록 **2개**뿐이라 그대로 넣으면 내용의 96%가
조용히 사라진다.

**어떻게.** 표 `text`(탭 구분)를 행 단위로 ≤1,400자 그룹으로 묶고, 각 그룹 앞에
그 표의 헤더행을 붙여 청크가 자체 설명적이 되게 한다. 다단 헤더도 처리한다 —
`건강 전상품`은 헤더가 2행(`… | 일반심사형 | 일반심사형 | …` + `… | (당사) 한도반영 기준 | (신정원) 반영기준 | …`)이라
셀 수가 같고 절반 이상 동일하면 같은 헤더의 연속 행으로 보고 다른 부분만 ` / `로 이어붙인다.

## C3. 청크 길이 하드 캡 (`MAX_CHARS = 3800`)

**왜.** 같은 4,096자 절단 문제. 기존 신한 코퍼스는 11.6%(326건, 최대 161,443자)가
색인 시 잘려 알려진 교란 요인으로 남았다. 이번에는 사후 해명이 아니라 사전 차단한다.
자른 경우 ` …[truncated]` 마커를 남긴다 — 조용히 자르면 에이전트가
"표에 그 항목이 없다"고 잘못 결론 낸다.

**결과.** gold 절단 **0건** (최대 1,399자). distractor는 338건을 명시적으로 절단했다.
distractor도 자르는 이유: 그대로 두면 노이즈의 96%가 색인 단계에서 조용히 사라져
검색이 실제보다 쉬워지고 recall이 부풀려진다.

## C4. 전폭 병합셀 행 축약 + 중복 블록·중복 청크 제거

**왜.** 스프레드시트 export가 병합 셀 값을 그 행의 모든 열에 복제한다.
`기계약`의 8,501자 블록은 `○ 질병을 보장하는 담보는…` 한 문장이 13열에 반복된 것이고,
`간편예외질환`의 1,897행 표 상당 부분도 같은 형태다. 또 문서 내 완전중복 블록이 35%다
(`간편예외질환`은 page 0과 page 1의 블록이 **바이트 단위로 동일**).

중복을 남기면 중복본이 gold보다 먼저 뜨는데 정답 id는 하나뿐이라 **recall이
과소평가**된다. 기존 신한 코퍼스가 중복 21.8%로 recall을 최대 6%p 낮게 보고한 것과 같은 실패다.

**어떻게.**
- 비어있지 않은 셀이 전부 같은 값인 행 → 셀 1개로 축약
- **인접한 같은 값 셀은 축약하지 않는다** — `가능 | 가능`처럼 정당한 반복이 있어
  열 정렬이 깨진다
- 문서 내 완전중복 블록 skip, 전역 완전중복 청크 제거(첫 등장 유지)
- 내역은 `audit_duplicates.json`

**결과.** 중복 블록 156건 skip, 중복 청크 **144건** 제거.

## C5. 파서 노이즈 제거 — 단, score는 지우지 않는다

**왜.** 세 종류의 확인된 노이즈가 있다.
1. **파서 환각**: 한국어 보험 공문에 `[Fig. 1] A schematic of the experimental setup.`
   라는 영어 실험 캡션이 삽입돼 있다.
2. **푸터·라우팅**: `1p`, `수 신 처 : @신한라이프_전체`, 맨 전화번호 `02-3455-467`.
   검색 가치는 0인데 어휘적으로는 질의에 걸린다.
3. **의미 없는 블록**: `___`, `ㄱ`, 빈 문자열.

`문서 번호`·`발신 일자`·`담당`·`제목`은 **남긴다** — 공문의 실질 정보다.

`parser_score`(PDF 0.34~1.0)는 **필터링에 쓰지 않고 값만 보존**했다. 낮은 score를
지우면 그 효과를 나중에 보고할 수 없다.

## C6. `section_path` 복원

**왜.** 파싱본에 계층 정보가 전혀 없다. `retriever.index()`는 `title + text`를
함께 임베딩하는데(`retriever.py:88-98`), `건강 전상품` 316청크가 전부 같은 title이면
title 기여분이 노이즈가 되고 gold 사람 검수도 불가능하다.

**어떻게.** `header`/`paragraph_title` 블록(≤120자)을 본문이 아니라 섹션 스택으로
소비하고, markdown `#` 개수로 레벨을 잡는다. xlsx는 헤딩 블록이 없으므로
**페이지의 첫 블록**에 있는 짧은(≤80자) 전폭 병합 제목만 시트 제목으로 승격한다.

> 이 "첫 블록만" 제약이 핵심이다. 처음에는 표의 전폭 병합 주석을 모두 승격했더니
> `유의FC : 가입불가`, `보장계약 ①번과 동일` 같은 **데이터 셀 값**이 section_path에
> 들어가고 그 값이 title을 통해 임베딩에 섞였다. 지금은 시트 제목
> (`대상년월 : 26.07`, `기계약 합산 가입한도`, `■ 7월 주요 변경사항 요약`)만 남는다.

## C7. `parent_id`를 만들지 않는다

**왜.** `parent_map_from_corpus`(`run_experiment.py:156-165`)는 `parent_id != _id`인
문서만 보고 평가 단위를 parent로 바꾼다. 넣는 순간 청크 단위 지표가 깨지고
기존 신한 결과와도 비교 불가가 된다. 문서·섹션 정보는 `doc`/`section_path`/`page`
별도 필드로 보관한다. `*_parent_ids.json`도 만들지 않는다
(존재하면 `load_corpus`가 parent 분기를 타 subset이 무시된다).

## C8. 질의 표본 — 문서별 round-robin + element_type 층화

**왜.** gold 청크 563건 중 `건강 전상품`(316) + `간편예외질환`(137)이 80%다.
비례 추출하면 사실상 스프레드시트 두 개만 평가하게 된다.

**어떻게** (`scripts/build_shinhan_uw_qa.py`). 문서별 round-robin(문서당 상한 10),
층 목표 `table 35 / non_table 15`, 후보는 150자 이상, distractor는 제외.
프롬프트·verbatim span 검증·qrels score는 `build_shinhan_qa_v2.py`와 **동일하게**
유지했다 — gold 생성 절차를 바꾸면 방법론이 어긋난다.

**결과.** 질의 50건, **7문서 전부** 포함(1~19건), 층 `table 42 / text 7 / figure 1`,
supporting span 60개 중 **60개가 원문 그대로(verbatim 100%)**.
층 목표를 다 못 채운 이유는 비표 후보가 27건뿐이기 때문이며 실제 분포는
`qa_manifest.json`의 `stratum_actual`에 기록했다.

## C9. distractor ID 네임스페이싱

**왜.** 두 코퍼스의 `_id` 형식이 똑같이 `<8hex>_<sss>_<cc>`라서 충돌 시
corpus dict가 **조용히 덮어써진다**. `shinhan-legacy::` 접두사를 붙인다
(`build_shinhan_mixed.py:155-166` 패턴).

## C10. 자기 검증

빌더가 실패로 끝나는 조건: `_id` 중복 / `parent_id` 존재 / `MAX_CHARS` 초과 /
subset ≠ corpus / 결정론적 metadata·태그가 일부 청크 누락 / gold에 distractor 접두사 혼입.
QA 빌더: gold ⊄ corpus / gold에 `::` 포함 / 같은 청크가 두 번 gold.

## 정제 결과

| 항목 | 값 |
|---|---|
| gold 청크 | **563** (7문서) |
| distractor 청크 | 2,802 (`shinhan-legacy::`, 노이즈 전용) |
| 전체 | **3,365** |
| element_type | `table` 502 · `text` 60 · `figure` 1 |
| parser_label | `table` 508 · `table_note` 42 · `text` 12 · `infographic` 1 |
| 청크 길이 | p50 1,260 · p95 1,391 · max 1,399 (총 586,706자) |
| 제거된 중복 청크 | 144 |
| 절단 | gold 0 / distractor 338 |
| 질의 | 50 (질의당 gold 1) |

문서별 gold 청크: `건강 전상품` 316 · `간편예외질환` 137 · `메디컬UW` 54 ·
`기계약 합산한도` 44 · `건강진단기준` 6 · `인수 기준 안내` 5 · `중대질환` 1

### element_type 판정 규칙 (결정론적)
- 파서 `label == table` **이고** 병합셀 축약 후 헤더 ≥2셀 · 데이터 ≥1행 → `table`
- 파서 `label == infographic` → `figure`
- 그 외(축약 후 표가 아닌 것 포함) → `text`

`label == table`인데 `text`로 내려간 42건이 `parser_label == table_note`다 —
전폭 병합 주석 셀이 표로 잡히는 것을 막는다.

## 남는 한계 (보고 시 반드시 함께 쓸 것)

1. **후보 풀이 작다.** 3,365청크에서 top-20은 코퍼스의 0.6%다. recall이 높게 나오면
   "증강이 효과적"이 아니라 **천장 효과**를 먼저 의심할 것.
2. **코퍼스 편중이 남는다.** 질의는 문서별 균등으로 뽑아 상쇄했지만 코퍼스 자체는
   두 스프레드시트가 gold의 80%다.
3. **distractor 도메인이 완전히 같지 않다.** distractor(기존 신한 28문서)는 약관·상담자료
   중심이고 gold는 언더라이팅 인수기준이다. recall이 잘 떨어지지 않으면
   "규모에 강건"이 아니라 **"distractor가 쉬웠다"**를 먼저 의심할 것.
4. **distractor 원본 한계 상속** — 중복 청크 21.8%, 단일 문서가 49.8% 차지.
5. **`parser_score`는 PDF에만 있다** (xlsx/pptx는 null). score 기반 분석은 3개 문서로 제한된다.
6. **gold는 gpt-4o-mini 단일 생성, 사람 검수 없음.** 질문이 gold 청크로부터
   생성되어 어휘 중복이 크다 — 검색이 실제보다 쉬울 수 있다(기존 신한·법률과 동일한 한계).
7. **질의 50 × gold 1 ⇒ 분해능 2%p.** "효과 없음"과 "표본 부족으로 판정 불가"를
   구분해 서술할 것.
8. **절대 점수 비교 금지** — 법률 Part(parent 단위)와도, 기존 `shinhan`(다른 문서·파서·청킹)과도.
9. **리랭커 비대칭** — hybrid만 리랭킹하고 에이전트 pull 경로엔 리랭커가 없다
   (`run_experiment.py:562-563`).
10. **해석 금지 지표** — `density@k`·`span_f1@k`는 분모가 top-k 총 길이라 이론상 최대 ≈0.002
    (`span_metrics.py:75`), `coverage@k`만 해석한다. `avg_efficiency`는
    `gold_recall / pull_count`라 1-pull hybrid가 구조적으로 이긴다.
