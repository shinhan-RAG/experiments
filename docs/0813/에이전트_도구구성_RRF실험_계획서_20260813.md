## 1. 한 문장 요약

시맨틱 태그 기반 **구조 검색**과 메타데이터(v6/v9) 기반 **의미 검색**을 RRF로 융합하되, **에이전트에게 주는 도구 조합을 바꿔가며** 어떤 도구 구성이 검색 성능을 가장 높이는지 비교한다.

## 2. 배경과 동기

### 2-1. 지금까지의 실험 여정

| 단계 | 핵심 결과 |
|---|---|
| 시맨틱 태그 (s0~s1k4r2 → CLM-lexical S5) | **CLM S5 NEW** R@5=.6667 (에이전틱, n=30). 결정론적 CLM core118 R@5=.4322 |
| 메타데이터 (v6~v13) | dense-only V9_QSURF R@5=.6369 1등. **에이전틱에서는 기준선(.6535)보다 낮음**(.6040). 도구가 같으면 색인 내용을 바꿔도 에이전트 행동이 차이를 흡수 |
| 결정론적 RRF | BM25+BGE-M3 dense RRF k=5로 에이전트 변동 제거. TAG+META 융합 R@20=71.6% (341건 기준) |
| v13 Boundary Evidence Card | 세 arm 모두 기준선 대비 비유의(Holm p≥0.29). v13 경로 **기각** |

### 2-2. 핵심 발견 — 오라클 합집합의 머리공간

2026-08-12 에이전틱 재측정 (n=202, claude-sonnet-5):

| 구분 | R@1 | R@5 | R@10 | MRR@10 |
|---:|---:|---:|---:|---:|
| A0_BASE (최고 단독) | .3960 | .6535 | .7129 | .5069 |
| A6_HIER2 (최고 메타) | .3861 | .6683 | .7079 | .5093 |
| **7-arm 오라클 합집합** | **.6634** | **.8812** | **.8960** | **.7565** |

오라클 합집합 R@5=.8812 — 최고 단독 arm(.6683) 대비 **+21.3%p의 머리공간**이 있다.

### 2-3. 원인 진단 — vector 도구 사용률

실측 도구 분포 (agentic-v3, n=202×3arm, 평균 호출 4.6~4.9회):

| 도구 | 호출 비율 |
|---|---|
| grep | **45%** |
| read | **47%** |
| vector | **8%** |

에이전트는 vector를 거의 안 쓴다. grep으로 본문을 직접 보완할 수 있어 **색인(v6/v9) 차이가 에이전트 행동에 흡수되는 기계적 원인**이다. 따라서 색인 내용만 바꾸는 접근은 한계가 있고, **도구 자체를 설계 변수로** 다뤄야 한다.

### 2-4. 이 실험의 질문

> **에이전트에게 어떤 도구 조합(v6 vs v9 색인 + 구조 검색 도구)을 주어야 오라클 합집합(.8812)에 가장 가까워지는가?**

## 3. 연구 가설

### H1 — 메타데이터 스키마 효과

> v6(5필드 서술형)과 v9(질의 층위 3층)를 dense 색인으로 각각 사용할 때, 에이전틱 검색에서 기준선(A0_BASE) 대비 유의한 R@5 차이가 발생하는가.

근거: dense-only에서 V9_QSURF가 R@5=.6369로 1등이었으나 에이전틱에서는 기준선 이하. vector 호출률 8%라는 실측으로 볼 때 다른 도구 조합에서는 결과가 달라질 수 있다.

### H2 — 도구 분화 가설

> 에이전트에게 기존 grep 대신 `structured_search`(semtag 슬롯 기반 구조 검색)를 주면, 정규식을 직접 작성하지 않아도 의미적 필드 조합으로 검색할 수 있어 R@5가 올라갈 것이다.

근거: CLM S5 NEW의 결정론적 R@5=.4322 → 에이전틱 R@5=.6667으로, 에이전트가 태그 기반 후보를 활용했을 때 +23.5%p 상승이 관측됨.

### H3 — 자동 융합 하한 가설

> 에이전트 상위 결과를 보존하고 나머지 칸을 결정론적 RRF로 채우는 **안전망(FLOOR)** 구조가, 에이전트 단독보다 **안정적으로 높은** R@10을 줄 것이다.

근거: 에이전트 세션 간 변동이 크다(기존 BASE 재실행 간 17%p 차이 관측). RRF 하한이 보장되면 최악 시나리오를 방어할 수 있다.

## 4. 실험 arm 설계

### 4-0. 공통 조건

| 항목 | 값 |
|---|---|
| 에이전트 모델 | Haiku 4.5 via Claude CLI (또는 KT Cloud LLM) |
| 호출 상한 | 8회/세션 |
| 청크셋 | fixed600 (600자/100겹침, 5,335청크) |
| 임베딩 | dragonkue/BGE-m3-ko (캐시 재사용, 재임베딩 0회) |
| 출력 | top-10 ranked chunk_ids |
| 평가 분모 | v3 core_retrieval train (n=202) / 보조: elem chunkset |
| 채점기 | `eval.py` + `qa_gold_v3.jsonl["fixed600"]` (공식) |

### 4-1. 에이전틱 arm (세션 발생)

| Arm | 도구 구성 | dense 색인 | lexical/구조 도구 | 목적 |
|---|---|---|---|---|
| **T0-BASE** | vector + grep + read | `vec_fixed600_A0_BASE` (원문) | grep(원문 view) | 이 실험 내부 기준선 |
| **T1-V6** | vector + grep + read | `vec_fixed600_J2_JSONPURE` (v6) | grep(v6 view) | v6 메타데이터 arm |
| **T2-V9** | vector + grep + read | `vec_fixed600_V9_QSURF` (v9) | grep(v9 view) | v9 메타데이터 arm |
| **T3-STRUCT** | vector + **structured_search** + read | 파일럿 승자 색인 | semtag 슬롯 필터 → chunk_id | 도구 분화 가설 (H2) |

> T3-STRUCT는 **파일럿에서 T0 대비 −10%p 이상 열등하지 않을 때만** 본실행에 진입한다.

### 4-2. 비에이전틱 (LLM 0회, 비용 ~$0)

| Arm | 설명 |
|---|---|
| **C0-RRF-DET** | dense + BM25 lexical → RRF k=5, 에이전트 없음. 결정론적 대조군 |
| **F-FLOOR** | 각 에이전틱 arm의 상위 K개 보존 + C0-RRF-DET로 나머지 채움. **별도 세션 아님 — 사후 재채점** |

### 4-3. T4-FLOOR를 사후 재채점으로 구현하는 이유 (T5-AUTORANK 기각)

1. **추가 토큰 0.** T5-AUTORANK는 auto_rrf 1회 호출로 ~2,500자 preview가 컨텍스트에 들어가 세션당 +10K 입력 토큰(+11%). F-FLOOR는 기존 세션 로그만 재사용.
2. **모든 arm에 동시 적용.** T0/T1/T2/T3 각각에 대해 F-FLOOR를 산출 → 세션 1세트로 2배 증거.
3. **Haiku 특성.** Haiku는 sonnet 대비 도구 선택 품질이 낮을 가능성 — 에이전트가 약할수록 안전망의 정보가치가 커지고, 자율 RRF(T5)의 정보가치는 줄어든다.
4. **퇴화 위험 없음.** T5의 "auto_rrf 결과 그대로 제출" 퇴화를 구조적으로 회피.

K(에이전트 보존 칸 수)는 파일럿에서 {3, 5, 10}을 스윕 후 본실행 전에 동결한다.

## 5. 우주 정렬 — 단일 진리원

### 5-1. 결정

> **모든 arm, 모든 널, 채점기가 공유하는 단일 우주: `fixed600` 청크(5,335) + `qa_gold_v3.jsonl["fixed600"]` + `eval.py`(공식).**
> 분모: split=train & core_retrieval = **n=202**.

이유:
- v6/v9/base 벡터·뷰가 **fixed600으로만** 캐시돼 있다. 다른 우주로 옮기면 재임베딩 필요.
- .6535(A0 baseline)와 .8812(7-arm 오라클) 머리공간이 정의된 우주가 이것.
- 공식 채점기가 `chunk_id` 단위로 동작.

### 5-2. chunk_id ↔ element_id 브리지 (T3-STRUCT용)

semtag 태그(`tags_run1.jsonl`)는 `elements_rev4`(5,924) element_id 기준, dense/grep은 fixed600 chunk_id 기준이다.

```
elements_rev4.jsonl (element_id, line_start, line_end)
        │  라인 스팬 겹침 (deterministic, LLM 0회)
        ▼
chunk_map_rev4_to_fixed600.json : {element_id → [chunk_id, ...]}
        │
structured_search(filters) → element_id 후보 → 맵으로 chunk_id 전개 → 반환
```

- 에이전트는 **끝까지 chunk_id만 본다.** 프롬프트·출력 스키마 변경 없음.
- Preflight 게이트: (a) 미매핑 element < 1%, (b) 재앵커링 gold(n=337) 전개 chunk가 qa_gold_v3 fixed600 gold와 겹치는 비율 ≥ 90%. 미달 시 T3-STRUCT 제외, 3-arm으로 축소.

### 5-3. 사용하지 않는 파일 (명시)

- `elements_semtag.jsonl` — 로컬 없음, MANIFEST SHA 없음. 이 실험은 이 파일에 의존하지 않음.
- `gold_mapped_noah_v3.jsonl` — 채점 gold 아님. 어떤 arm의 지표도 이 파일로 계산하지 않음.
- `v2ds30_noah_v3_train_anchored_full.jsonl` (n=337) — 브리지 검증용으로만 사용. 주 지표 산출에 쓰지 않음.

## 6. 신규 도구 명세

### 6-1. structured_search (T3-STRUCT 전용)

semtag CLM S5 NEW 태그(`tags_run1.jsonl`)를 기반으로 한 슬롯 필터 검색.

```
structured_search(filters: dict, top_k: int = 20)
  → [{chunk_id, score, matched_slots, preview}]
```

**활성 슬롯** (MANIFEST 근거 — 질의측 생성률 > 0.03인 것만):

| 슬롯 | 역할 | 예시 |
|---|---|---|
| `contract` | 특약/주계약명 (fuzzy) | "암진단특약" |
| `subject` | 급여금/보험금 명칭 | "수술급여금" |
| `role` | 의미역 | "payment_trigger" |
| `qualifier` | 조건/수치/기간 | "80% 이상" |
| `schema` | 엘리먼트 유형 태그 | "table_row" |

**비활성** (질의측 생성률 ≈ 0): `article`, `reference`, `table`

동작: 슬롯 간 AND, 슬롯 내 OR. CLM 조정수준 정렬(matched slot count 내림차순, 문서 순서 tiebreak). element_id → chunk_id 브리지 전개 후 chunk_id로 반환.

> **주의**: semtag 우승 조합(S5/CLM)에서 **에이전트는 태그를 보지 못했다 — 태그는 오프라인 정렬 함수의 입력**이었다. 이것을 에이전트 **도구로** 주는 것은 우승 조합의 재현이 아니라 **새 조건**이다.

### 6-2. auto_rrf — 미구현 (기각)

T5-AUTORANK 기각으로 구현하지 않는다 (§4-3 참조).

## 7. 에이전트-RRF 통합: F-FLOOR 사후 안전망

```
에이전트 세션 → ranked_chunk_ids[:K] 보존
C0-RRF-DET top-N 생성 (결정론적, 사전 계산)
에이전트 상위 K개 + RRF에서 중복 제거 후 채움
→ 최종 top-10
```

- K: 파일럿에서 {3, 5, 10} 스윕 후 동결.
- 진단: `displacement()` (`hybrid-v7/fuse.py:63`)로 "얻은 gold / 밀려난 gold" arm별 보고.
- **해석 원칙**:
  - C0-RRF-DET R@5 > 모든 에이전틱 arm R@5이면, 에이전트가 오히려 방해.
  - F-FLOOR R@5 > 해당 arm raw R@5이면, 안전망이 에이전트 실패를 보완.

### 9-4. 반복 횟수 2회의 통계적 대가

- 3회 평균 대비 2회 평균은 문항별 표준오차 1.22배 증가. 실효 MDE: **5.6%p → 6.8%p**.
- 규칙: 2회로 시작, G5(안정성: 회차 간 R@5 max−min < 5%p) 미달 arm만 3회차 추가. 이 규칙은 사전등록에 기록.

## 10. 통계 검정

| 항목 | 방법 |
|---|---|
| 주 검정 | McNemar 정확검정, 양측, α=0.05, Holm 보정 |
| 비교 쌍 | **4쌍 사전지정**: T1-T0, T2-T0, T3-T0, F-FLOOR(best)-best(raw) |
| 보조 | paired bootstrap 10,000회 95% CI (ΔR@5, ΔMRR@10) |
| 주 지표 | **R@5** (사전등록) |
| 병기 지표 | R@1, R@10, R@20, MRR@10 |
| 최소 검출 효과 | n=202, 2회 반복 기준 실효 MDE ~6.8%p |

> 이 프로젝트에서 결론이 분모에 의해 뒤집힌 실증:
>
> | 분모 | A0_BASE R@5 |
> |---|---|
> | v3 train core (n=202) | .6535 |
> | train single_chunk core (n=163) | .5706 |
> | semtag core118 (결정론) | .4153 |
>
> 규칙: 모든 표에 `n=`을 병기. 주 분모 n=202 core + **보조 분모 `--chunkset elem` 재채점 1세트 병기**. 두 분모에서 부호가 반대면 "개선"이라 쓰지 않는다.

## 11. 성공 기준과 게이트

### Phase 1 게이트

| 게이트 | 조건 | 의미 |
|---|---|---|
| G1-방향 | 최고 arm 2회 평균 R@5 > T0-BASE 2회 평균 R@5 | 방향 일치 |
| G2-효과 | 2회 평균 R@5 차이 ≥ **+5%p** | 실질적 개선 |
| G3-유의 | McNemar paired p < .05 (Holm 보정 후) | 통계적 유의 |
| G4-널초과 | 최고 arm R@5 > constant_dummy R@5 | 도구/enrichment 기여 확인 |
| G5-안정 | 최고 arm 회차 간 R@5 max−min < 5%p | 세션 변동 허용 범위 |

G5 미달 시 3회차 추가(사전등록 규칙).

> **기준선은 과거 sonnet .6535가 아니라 이 실험의 Haiku T0-BASE로 재정의한다.** 모델이 다르면 절대 수준이 다르다. 목표치는 T0 실측 확정 후 채운다.

## 18. 하지 말 것

1. Train에서 고른 최고 구성을 바꾸지 않는다
2. 에이전트 세션 실패를 선별 재실행하지 않는다
3. 반복 중 좋은 회차만 골라 보고하지 않는다
4. 결정론적 RRF 대조군 없이 에이전트 결과만 보고하지 않는다
5. 널 대조 없이 개선을 확정하지 않는다
6. 과거 에이전틱 결과(.6535/.6683/.8812)를 이 실험의 대조군으로 직접 사용하지 않는다 — 배경으로만 인용
7. 도구 반환 결과를 세션 로그에 저장하지 않고 실행하지 않는다
8. 단일 분모로만 판정하지 않는다 — 분모가 결론을 뒤집을 수 있다
9. "개선"이라는 단어를 paired 신뢰구간이 0을 포함하는 경우에 사용하지 않는다
10. 에이전트가 아무 도구도 안 쓴 세션을 제거하고 평균을 다시 내지 않는다
11. **다른 백엔드(CLI/HTTP)나 다른 모델(Haiku/Sonnet)로 얻은 결과를 같은 표에서 비교하지 않는다**
12. **`elements_semtag.jsonl`·`gold_mapped_noah_v3.jsonl`로 주 지표를 계산하지 않는다**
13. **본실행 결과를 본 뒤 K(FLOOR 보존 칸 수), RRF 가중치, 슬롯 목록, 반복 횟수 규칙을 바꾸지 않는다**

## 19. 해석 시 주의점

1. 모든 arm은 **단일 문서**(250212 판매약관) 기준이다. ~9,400문서 환경에서 같은 결과가 나온다고 볼 수 없다.
2. 에이전트 모델이 **Haiku 4.5**이다. Sonnet과 도구 사용 패턴이 완전히 다를 수 있으며, 과거 Sonnet 수치와 직접 비교하면 안 된다.
3. semtag 우승 조합에서 에이전트는 태그를 보지 못했다(오프라인 정렬 입력). structured_search 도구는 **다른 조건**이다.
4. core_retrieval=True는 193/202가 evidence group 1개인 **쉬운 층**이다.
5. C레벨 수치는 문서 1건 선택이 이미 끝났다는 가정이며, 110K 문서 환경에서의 A/B 퍼널은 별도 실험이다.
6. structured_search는 시맨틱 태그 품질에 직접 의존한다. 태그 생성 품질이 낮으면 효과가 과소 추정된다.
