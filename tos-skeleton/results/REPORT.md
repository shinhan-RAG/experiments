# 약관 뼈대+슬롯 구조화 실험 — 1차 결과 (원(ONE) 17벌)

2026-07-31. 데이터: 신한(간편가입)통합건강보험 원(ONE) 판매약관 17벌
(대면 6 / TM 6 / 무채널 5, 250401→260507, 각 ~2,000p).
파이프라인: pdftotext(결정적) → 정규화 → 단위(주계약/특약)·조(條) 분해 →
반복 LCS로 뼈대 귀납 → 슬롯 값 추출 → 라운드트립 검증.
코드: `scripts/extract.py`, `segment.py`, `induce.py`.

| 지표 | 값 |
|---|---|
| 라운드트립(뼈대+슬롯+override → 원문 복원) | **40,044/40,044 = 100% 무손실** |

## 발견

1. **채널 차이 = 0.** 대면판과 TM판은 본문이 조 단위로 완전 동일 (표지·페이지헤더만 다름).
   채널은 뼈대 분기가 아니라 메타데이터 1개 필드다.
2. **개정은 이벤트 단위로 몰린다.** 내용 변경 422개 조의 버전 분할 시그니처가 20종뿐이고
   3개 이벤트가 93%를 설명:
   - 260209 KCD 9차 개정 적용 — 294조 (질병 정의·진단확정 조들이 일괄 변경)
   - 250701 특약 라인업/명칭 개편 — 67조 (준용 조의 특약 목록)
   - 두 이벤트 모두 — 32조
   - 매판 바뀌는 조는 7개 (발행일·이율류) → 이것이 진짜 "버전별 슬롯"
3. **슬롯 키는 재발한다.** 최다 슬롯 조는 `제2-12조 주계약 약관 규정의 준용`(109개 특약에
   동일 패턴) — "부가특약 목록"이라는 하나의 키가 특약마다 반복. KCD 조는
   `kcd_edition / kcd_notice_no / kcd_effective_date` 슬롯이 그대로 떨어짐
   (8차·제2020-175호·2021.1.1 → 9차·제2025-299호·2026.1.1).
4. **잔차(전 버전 공유 안 되는 조) 2,647개의 정체는 특약 구성 변화** — 버전이 지나며
   특약이 추가/제거된 것. 뼈대 실패가 아니라 "이 버전에 이 특약이 있는가"라는
   구성(bill of materials) 정보로, 상품×버전→특약 목록 테이블로 자연스럽게 표현된다.

## 한계·주의

- PDF 줄바꿈 위치 차이가 가짜 슬롯을 만든다('보 험금' vs '보험금'). 조 단위 판정은
  공백 무시로 해결했으나 슬롯 수(1,140)에는 레이아웃 슬롯이 섞여 있음 —
  값 정규화(공백 제거 비교) 후 실질 슬롯은 훨씬 적다.
- 정렬 실패(align_fail)는 17벌에서 1개 조뿐 — override로 무손실 유지.
- 조 키에 제목을 포함해 제목 표기 변화 시 다른 조로 갈라짐 (잔차 과대집계 요인).
- 이 결과는 단일 상품 내 버전·채널 축. **상품 간 키 일반화(3단계)는 미실시.**
