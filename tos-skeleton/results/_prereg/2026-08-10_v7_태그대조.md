## 3. 태그 스키마 — 무엇을 넣는가

### 3-1. 채택 필드 — **둘만**

```
SCOPE:<특약>  JO:<조>
```

| 필드 | 근거 |
|---|---|
| `SCOPE` (특약 118종) | 유일하게 질의 도출 여지가 있는 축 (규칙 라우터 top-1 `.462`) |
| `JO` (조 206종) | 무충돌률 기여가 가장 큼 (`.019 → .081`) |

**비메타 토큰을 쓴다.** 기존 `[특약]`은 `rg`에서 **정규식 문자 클래스로 해석돼 0건**을 반환했다(`[특약]주계약` 0 vs `\[특약\]주계약` 253).

### 3-2. 제외 필드 — 사유 명기

| 필드 | 제외 사유 |
|---|---|
| `[역할]` | 보유율 `.440` · 필터 후 후보 1,639(거의 안 좁힘) |
| `[유형]` | 질의 도출 규칙 없음 |
| `[키]`·`[정의어]`·`[표]` | `s1k2` vs `s0` 순 Δ `−1` |
| **`[묻는말]`** | `s2q` 순 Δ `−11`. **설계서 (c)가 배제하라는 "동의어" 그 자체** |
| **급여금** | 추출기가 문장 조각을 삼킴(`2조(보험금` 175건 · hapax 56.8%). **크기정합 널 미달** |

### 3-3. 설계서 (c) — 직렬화 순서

**태그 내부 필드 순서를 바꾼 arm을 넣는다.** 설계서가 "직렬화 순서를 고정하라"고 요구하는데, **무엇으로 고정할지는 측정된 적이 없다.**

## 4. arm — **3개. 뷰의 태그 칸만 다르다**

| arm | 뷰 |
|---|---|
| **`notag`** | `eid \|  \| 본문` ← **v5 `budget`을 그대로 재사용. 신규 발사 없음** |
| **`tag`** | `eid \| SCOPE:<특약> JO:<조> \| 본문` |
| **`tagrev`** | `eid \| JO:<조> SCOPE:<특약> \| 본문` ← 설계서 (c) 직렬화 순서 |

### 4-1. 뷰 검증 — 생성 직후 `assert`

```python
assert len(v_tag) == len(v_tagrev) == len(v_notag) == 6852
for a, b, c in zip(v_notag, v_tag, v_tagrev):
    assert a.split(" | ")[0] == b.split(" | ")[0] == c.split(" | ")[0]      # eid 동일
    assert a.split(" | ", 2)[2] == b.split(" | ", 2)[2] == c.split(" | ",2)[2]  # 본문 동일
    assert set(b.split(" | ")[1].split()) == set(c.split(" | ")[1].split())     # 토큰 동일, 순서만 다름
assert "[" not in "".join(l.split(" | ")[1] for l in v_tag)     # 정규식 메타문자 없음
```

**실패하면 실행하지 마라.**

### 4-2. 프롬프트 — **v5 `base` 공통** (발사 전 수정 · 아래 §4-3)

**`v5 base` 프롬프트 SHA `c5590629bb8888c6`를 3 arm 공통으로 쓴다.** 최대 10개 반환.
`notag` arm은 **`v5 base` 세션을 재사용**한다(신규 발사 없음).

**마커 이름을 프롬프트에 박지 마라** — `notag`에서 거짓이 된다.

### 4-3. 발사 전 수정 기록

**초판 §4-2는 `v5 budget` 프롬프트 SHA `31e060d2`(정확히 5개 반환)를 지정했다. 오류다.**

| | `base` | `budget` |
|---|---|---|
| 반환 | 최대 10개, 평균 **3.92** | **정확히 5개** |
| `R@10` | .4262 (vs `R@5` .4167) | **`≡ R@5`** |
| **`MRR@10`** | **유효** | **`≡ MRR@5`** |

§5-2가 정한 주 지표 3개 중 **`R@10`·`MRR@10` 두 개가 정의상 퇴화**한다.
§7의 "반환 개수를 5로 고정하지 마라"와도 정면 충돌한다.

**이 수정은 실행 세션이 발사 전에 모순을 보고해 이루어졌다. 사후 변경이 아니다.**

**동반 요구 3건**

1. **한계 명기** — `base`는 평균 3.92개를 반환하므로 `R@10`의 여유가 작다. 사실상 `R@4` 수준이다. `MRR@10`은 순위 기반이라 유효하다
2. **환경 드리프트 확인** — v7 `tag` arm과 재사용하는 `v5 base`의 **도구 호출 분포 · 턴 수 · 세션당 비용 · 캡 포화율**을 대조. 유의한 차이가 있으면 **`notag` 재사용을 무효로 하고 보고**한다
3. **SHA `assert`** — 뷰 · 도구 · 프롬프트 SHA가 `v5 base`와 동일함을 확인하고 결과 JSON에 기록

### 5-3. 주 대조 — **2개**

| | 대조 | 지표 |
|---|---|---|
| **H1** | **`tag` vs `notag`** | 확정 210 `R@10` |
| **H2** | `tag` vs `tagrev` | 확정 210 `R@10` |

**짝지은 McNemar 정확검정, 양측, Bonferroni α = 0.025.**
효과 크기는 **bootstrap 95% CI** 병기. 그 외 전부 기술통계 + Wilson CI, **`p`값 금지.**

### 5-4. ★ 집계 — v5의 실수를 반복하지 않는다

> **회차 라벨은 정보를 담지 않는다.** `Δ_r1 + Δ_r2`는 회차 분할에 불변이다.
> **주분석은 문항별 2회 평균의 짝지은 차(풀링).** 회차별은 잡음 산출용으로만 병기.

### 5-5. ★ 널 — **크기정합 널을 반드시 동반한다**

`기각_대장 §11` 규율.

| 널 | 산출 | 무엇을 가르는가 |
|---|---|---|
| **길이일치 널** — 태그 칸을 같은 길이의 `〇`로 | 신규 arm 불필요, **로그 재생** | 태그의 **의미**가 기여하는가 |
| **크기정합 널** — 태그 필터 후보와 같은 크기의 무작위 집합 (20시드) | LLM 0회 | 태그가 아니라 **`\|후보집합\|`**이 만든 이득인가 |
| **태그 순열 널** — 태그 값을 element 간 무작위 배치 (20시드) | 로그 재생 | 태그-본문 대응이 필요한가 |

> **셋 중 하나라도 못 넘으면 기각이다. "상한이 높다"는 채택 근거가 아니다.**

### 5-5-a. ★ 널 실측값 — **발사 전 동결** (`2026-08-10`)

**`v5 base_r1` 세션에 기록된 grep 패턴 685개(209문항)를 네 뷰에 재생했다. LLM 0회.**
**결과가 오기 전에 박아둔다. 사후 조정 여지를 없애기 위함이다.**

| 뷰 | ① 패턴이 정답 히트 | **② 줄순서 40 생존** | 히트 중앙 | 총 히트줄 |
|---|---|---|---|---|
| **`notag`** | .8756 | **`.7656`** | 52 | 148,082 |
| **`tag`** (`SCOPE:`/`JO:`) | .8852 | **`.7368`** | 62 | 214,659 |
| **`tagrev`** | .8852 | **`.7368`** | 62 | 211,740 |
| **널 · 길이일치** (`〇`) | .8756 | **`.7656`** | 52 | **148,082** |
| 널 · 순열 시드0 | .8852 | .6986 | 69 | 228,916 |
| 널 · 순열 시드1 | .8900 | .7033 | 68 | 228,700 |
| 널 · 순열 시드2 | .8852 | .7033 | 69 | 229,021 |

### 이 값이 확정하는 것

| # | |
|---|---|
| **1** | **태그를 넣으면 ①은 `+1.0%p` 오르지만 ②는 `−2.9%p` 떨어진다.** 히트가 `52 → 62`로 늘어 40줄 창에서 정답이 밀려난다 |
| **2** | **길이일치 널이 `notag`와 소수점까지 동일하다** (① `.8756` · ② `.7656` · 총히트 `148,082`). `〇〇` bigram이 어떤 질의와도 겹치지 않으므로 **grep에서 태그 칸이 없는 것과 물리적으로 같다** |
| **3** | **`tag`와 `tagrev`의 ①②가 완전히 같다.** 직렬화 순서는 grep 히트를 바꾸지 않는다. **H2에 차이가 나온다면 그것은 오직 ③(에이전트 판단)에서 온 것이다** |
| **4** | **순열 널이 `tag`보다 ②가 낮다** (`.6986~.7033` vs `.7368`). 태그–본문 대응이 ②에 약간 기여한다 |

### 5-5-b. 사전 예측 — **숫자를 먼저 박는다**

**② 순 Δ(`tag` − `notag`) = `−2.9%p`.** ③ 전환율이 유지되면 최종 `R@5`·`R@10`도 **음수**다.

```
예측    H1 순 Δ < 0
게이트 1 (+20문항)  발화하지 않는다
```

**예측이 맞으면 파일 검색에서 semantic tag는 종결이다. 틀리면 25라운드 만의 첫 양의 결과다.**

| # | 조건 |
|---|---|
| **0** | **`tag` `R@10` ≥ `notag` `R@10`** — 방향 |

| **2** | **`MRR@10`이 악화되지 않을 것** |

| 결과 | 판정 |
|---|---|

| **Δ < +15 또는 널 미돌파** | **파일 검색에서 semantic tag는 기여하지 않는다 — 축 종결** |
| **`notag`가 우세** | **태그가 해롭다** — `기각_대장` 등재 후 종결 |

### 5-7. 검정력

잡음 바닥 `π̂_d = .2238` [.181, .267] → 예상 `D ≈ 47`.
`D=47`에서 유의 최소 순 Δ **`+15`**, 80% 검정력선 **`+20`**.

**재생 기반 사전 예측: `notag` vs `SCOPE:` 태그의 ②(표시 생존) 순 Δ = `0 ~ +1`(n=137, 줄순서40).**
**즉 이 라운드는 게이트 1이 발화하지 않을 것으로 예상된다. 그것을 확인하는 것이 목적이다.**

> **예상이 맞으면 축 종결이고, 틀리면 25라운드 만에 첫 양의 결과다. 어느 쪽이든 정보가 된다.**
