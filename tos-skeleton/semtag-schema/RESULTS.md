## 관측

1. **concat 채널: 태그 길이에 단조 하락** — 문서 선택 층에서 3중 확인된 희석이
   element 층에서 4번째 재현. 같은 문서 내 element 간에는 태그 어휘(특약명·역할어)가
   수백 개 element에 공유되어 변별 기여 없이 길이 비용만 부과됨.
2. **any-token verify: 태그가 풍부할수록 하락** (s0 .2661 → k4 .2333) — 필드가 늘수록
   일반 토큰("청구"·"갱신")의 오탐 통과가 늘어 분할 선별성이 붕괴.
3. **선택적 verify(특약명·조항번호·코드·역할어휘만): 중립** (~.258, K1~K4 무변동) —
   고정밀 토큰은 안전하나 dev 질문에서 발화 빈도가 낮아 이득도 없음.
4. **세 어휘 채널 모두에서 어떤 스키마 변형도 원문 단독을 유의하게 넘지 못함.**
   PR #18의 TAG +6pt(에이전틱)와의 차이 해석: 태그의 가치는 어휘 유사도 질량이 아니라
   **에이전트가 구조화 질의를 조합할 수 있는 주소 체계**(실측: `[특약]X…[조항]Y` 패턴
   46회)에서 발생 — 어휘 채점 프록시로는 그 채널이 측정되지 않음.
5. 시사(설계 관점 기록): 단일 문서 내 태그 고도화의 목표는 어휘 추가가 아니라
   주소성(addressability) — 고정 마커 문법, 고정밀 필드(특약/조항/코드/역할 통제어휘),
   ≤200자 유지. 원문에 이미 있는 어휘의 재기입은 세 채널 모두에서 무효 내지 유해.

기제 분석(grep 패턴 전량 로그, s0 513회 / s2q 526회):
1. **예측 기제 불발** — 별칭 어휘가 든 grep은 s2q에서 6/526(1.1%)뿐. 에이전트는

3. **비용은 전면 부과** — 모든 element 줄이 길어져 모든 grep 출력에 별칭
   상용구가 실리고, 같은 역할 그룹 내 태그가 서로 더 비슷해져 변별 악화

설계 시사(기록): 별칭의 가치는 실험 3(어휘 채널 test +1.0%p)에 한정. 어휘 간극

우월 — 질의 측은 문서를 길게 만들지 않아 선별성을 보존(C4 라우터가 유일 채택인
