# Semantic Tag 구조·필드 고도화 실험 계획 (사전 등록, 2026-08-05)

목표: 단일 문서(원 ONE 260507) 내 element 검색에서 semantic tag의 구조·키·생성 규칙을
순차(1변수) 변형하며 성능 기여를 계측한다. 태그는 element당 직렬화 ≤200자.

## 입력 (고정)

- 문서: `판매약관_신한(간편가입)통합건강보험 원(ONE)…_260507.md` (SHA-256 기록)
- QA: `정답셋_359_최종_v4.xlsx` — 신뢰도=확정만 사용, quote-first 매핑(정규화 검색,
  다중 매치 시 [L라인] 최근접, 전 출처 실패 시 제외), gold=인용 구간과 겹치는 element 전부(any-hit)
- 분할: dev = PR #18 qa100 qid 집합(이미 튜닝에 사용된 소진 셋 — 반복 실험 전용),
  test = 나머지 매핑 성공분(동결, 최종 1회만)

## 평가 (내부 루프 = 결정적 프록시)

- 표현: `tag직렬화 + " ||| " + element원문` / 대조군 A0 = 원문만
- 랭커: 문자 bigram BM25(k1=1.2, b=0.75 — 기존 검증 구현과 동일 공식), 질의=질문 원문
- 지표: Recall@5·Recall@10(any-gold)·MRR@10, dev paired bootstrap 95% CI
- 에이전틱 평가는 범위 밖(실행 간 17pt 변동 실측) — 최종 후보의 확정 측정은 후속
- 채택 규칙(greedy): 각 스텝은 dev ΔMRR 점추정 > 0일 때만 승계, CI 병기, 전 조합 기록

## 순차 변형 축

| 스텝 | 변형 | schema_version |
|---|---|---|
| A0 | 태그 없음(원문만) | — |
| S0 | 대조: v2형 태그([특약][조항][역할] — 자유 역할) | tag.s0 |
| S1 | 마커 정규화 + [경로] breadcrumb 추가 | tag.s1 |
| K1 | +[역할] 통제어휘(≤3, 에이전트 grep 빈도 상위에서 도출) | tag.s1k1 |
| K2 | +[키] exact_keys(조항번호·질병코드·별표, ≤5, verbatim) | tag.s1k2 |
| K3 | +[정의어](「」·"~함은" 추출, ≤3) | tag.s1k3 |
| K4 | +표 특화(코드범위·표제목) | tag.s1k4 |
| R2 | 값 정규화(조항번호 공백 제거 이형 병기) | tag.s1k*r2 |

역할 통제어휘(고정): 지급사유, 정의, 납입면제사유, 보장개시일, 면책, 부담보, 감액,
무효, 진단확정기준, 제출서류, 청구절차, 갱신, 해지, 해지환급금, 보험금변경, 특약구성
