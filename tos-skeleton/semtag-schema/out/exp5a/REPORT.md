# 실험 5a — 페이지 헤더 노이즈 제거 (전처리)

일자: 2026-08-05 · 스크립트: `exp5a_pagehdr.py` · 전 과정 결정적(LLM/API 없음)

## 가설

PDF→md 변환 산물인 페이지 경계 블록("# SHINHAN LIFE" 줄, 독립 쪽번호 숫자 줄,
독립 "---" 수평선)이 element 텍스트에 끼어 문자 bigram 매칭에 노이즈를 만들며,
제거 시 dev 검색 성능이 오를 것이다.

## 방법

- 문서: `판매약관_…원(ONE)…_260507.md` (sha256 `279f134bedef…`, 249,047줄).
- 하네스: `semtag_experiment.py`에서 `nfc/split_elements/bigrams/BM25/boot_ci`
  import (수정 없음). 분할·eid·gold(`out/gold_mapped.jsonl`) 불변 —
  정제는 element text 내부의 라인 필터만, 판정은 원문 라인 번호·원문 문맥 기준.
- 제거 규칙(보수적, 원문 문맥으로 판정):
  - R1 header: strip이 정확히 `# SHINHAN LIFE`인 줄.
  - R2 pagenum: 숫자만 있는 줄 + 앞뒤 줄 공백(또는 문서 경계) + ±2번째 줄에
    페이지 경계 앵커(독립 `---` / `# SHINHAN LIFE` / `SHINHAN LIFE` /
    문서 제목 반복줄) 존재. 앵커 없는 독립 숫자(5건)는 보존.
  - R3 hr: strip이 정확히 `---` + 직전 줄이 공백이거나 이미 노이즈 판정
    (setext 밑줄 오인 방지). 표 구분행(`|---|`)은 strip이 `|`로 시작해 매치 불가.
- 평가: dev 96문항(=`qa100_gold.jsonl` qid ∩ gold_mapped), any-hit,
  R@5 / R@10 / MRR@10. paired 비교=문항별 RR 차이,
  bootstrap 95% CI(하네스 `boot_ci`, seed 20260805, n=10000). test 미평가.
- 게이트: A0 재현치가 R@5=0.3125, MRR@10=0.2647과 정확히 일치해야 진행.

## 관측

- 이 dev 셋·문자 bigram BM25 조건에서 가설은 지지되지 않았다. 성능은
  사실상 불변(R@5/R@10 동일, MRR −0.0002, CI가 0 포함)이다.
- 기제 해석(관측 범위 내): 질의는 한국어이고 노이즈 라인의 bigram
  (`SH`,`--`,숫자쌍 등)은 질의 bigram과 거의 교차하지 않으므로, 제거의
  영향 경로는 길이 정규화(dl/avgdl)뿐인데, 변경 element당 평균 19.1자
  감소는 element 길이 대비 작고 avgdl도 함께 줄어 순위가 거의 움직이지
  않았다. 유일한 변동(qid 240)은 top-10 내 미세 재배열이다.
- 가설의 "23%"보다 실제 오염 범위는 넓었다(element 기준 37.7%). 즉
  노이즈 존재 자체는 사실이나, 이 매칭 방식에서는 성능에 유의미한
  영향을 주지 않았다.

## 제약

- dev 96문항, 단일 문서, 단일 검색기(문자 bigram BM25)에서의 결과다.
  다른 표현(토큰 단위, 임베딩)이나 생성 단계에서의 효과는 측정하지 않았다.
- 보수 규칙으로 남긴 변형이 있다: 독립 `SHINHAN LIFE`(# 없는 변형, 858줄),
  문서 제목 반복줄(58줄)은 앵커로만 쓰고 제거하지 않았다. 앵커 없는 독립
  숫자 5건도 보존했다. 이들의 제거 효과는 본 실험 범위 밖이다.
- test 분할은 채점·보고하지 않았다.
