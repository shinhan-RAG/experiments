# 실험 계획: 에이전틱 서치에서 frontmatter 유·무 비교

## 배경

- 대상: 신한라이프 판매약관 원(ONE) 260507판 (4,242p, 주계약+특약 179개)
- 이미 있는 것: 약관에서 LLM으로 추출·검증(원문 대조 게이트 100% 통과)한 문서별
  frontmatter(key-value: document / 주계약·특약별 구성·급부). QA셋 359문항(질문+근거 quote).
- 선행 결과(참고): 고정 파이프라인(1홉 라우팅+BM25)에서 frontmatter 사용 시
  recall@10 +7.3%p (기준 .574 → .647), oracle 상한 .749.

## 목적

엘리먼트 단위로 잘린 약관에서, 에이전트가 **정답 엘리먼트를 잘 찾아가는가**를
frontmatter 유무로 비교한다.

## 주어지는 것 (딱 두 가지)

1) **frontmatter 파일** — 약관을 보고 만든 key-value. 값마다 근거 엘리먼트 ID 연결:

```yaml
document: {상품: 원(ONE), 버전: 260507}
주계약:
  급부: [{name: 사망보험금, trigger: ..., elements: [e0421, e0422]}]
특약:
  (간편)[기본]암진단특약(...):
    params: {간편: true, 환급: 미지급형}
    급부: [{name: 일반암진단급여금, trigger: 암 진단확정 시, elements: [e1205, e1206]}]
```

- 주계약 + 특약 179개 전부 커버, semantic tag 미사용
- elements 연결은 추출 시 검증된 근거 조(source)를 그 조에 속한 엘리먼트 ID로 변환

2) **엘리먼트들** — 같은 약관을 엘리먼트 단위(항·문단·표 블록, 조보다 잘게)로
자른 조각 전체. 각각 ID 보유.

## 비교 조건

| | A: frontmatter 없음 | B: frontmatter 있음 |
|---|---|---|
| 에이전트가 받는 것 | 질문 + 엘리먼트 더미 | 질문 + 엘리먼트 더미 + frontmatter |
| 기대 동작 | 키워드 검색부터 | frontmatter에서 key 찾고 연결 엘리먼트로 직행 후 확인 |

에이전트·도구(검색/읽기)·홉 한도(8)·모델은 완전 동일. 변수는 frontmatter 유무 하나.

## 절차

1. QA셋에서 정답 quote가 엘리먼트에 매핑되는 문항 사용 (파일럿 40, 특약/주계약 자연 비율)
2. 문항마다 A·B 실행, 에이전트가 근거 엘리먼트 ID 지목 시 종료
3. 정답 엘리먼트와 대조

## 지표

- 정답 엘리먼트 도달률 (주 지표)
- 홉 수(도구 호출 횟수), 시간·토큰
- 실패 유형: frontmatter에 key 없음 / 연결이 다른 조 가리킴 / 더미에서 헤맴

주의: frontmatter 연결은 급부가 적힌 조를 가리키며, 정답이 면책·갱신 조 등
다른 곳인 문항에서는 B도 특약 직행 후 주변 탐색이 필요 — 연결이 만능이 아닐 때의
출발점 가치도 자연 측정됨.

## 판정

- B 도달률 > A, 또는 동일 도달률을 더 적은 홉으로 → frontmatter 효과 입증
- 차이 없음 → frontmatter 가치는 검색 아닌 값 조회·개정 관리로 위치 조정

## 준비 작업

1. 엘리먼트 분할 (조 3,293 → 항·문단·표 블록, ID 부여)
2. QA quote → 엘리먼트 재매핑 (매핑률 보고)
3. 주계약 급부 LLM 추출 추가
4. source(조) → elements(ID) 변환
5. 세팅 실물 확인 후 파일럿 40 실행
